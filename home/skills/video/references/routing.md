# Routing by use case intent

Use the first matching use case.

| User wants | Route |
| --- | --- |
| A README demo, app walkthrough GIF, or screen recording for docs | `gif.md` |
| A specific edit to an existing HyperFrames project | `hyperframes.md`, then edit only that scope |
| Inspect, diagnose, preview, render, publish, or batch-render a HyperFrames project | `hyperframes.md` |
| Plain captions or subtitles on existing talking-head footage | HyperFrames captions flow |
| Designed overlays on existing talking-head, interview, or podcast footage | HyperFrames overlay flow |
| A beat-synced music video with no narration | HyperFrames music flow |
| A short unnarrated motion graphic, title, stat hit, chart hit, map hit, or lower-third | HyperFrames motion flow |
| A product, website, app, or company showcase from a URL or site brief | HyperFrames product flow |
| A topic, article, notes, concept, or listicle with invented visuals | HyperFrames faceless explainer flow |
| A presentation, pitch deck, or interactive deck | HyperFrames slideshow flow |
| A pull request or code change explanation video | HyperFrames PR video flow |
| A custom montage, sizzle reel, static loop, title card, footage remix, or longer piece | HyperFrames general flow |
| Images, logos, music, sound effects, voice, captions, grades, LUTs, or media treatments | `media.md` within the active route |

If the request is fresh and does not name the subject or source, ask one question.

If route choice is unclear, ask only for the intended deliverable.
